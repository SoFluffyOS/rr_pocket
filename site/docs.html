RR Pocket docs

RR Pocket runs the Flutter project on your computer on your Android phone, over Wi-Fi, with a stock flutter run -d pocket. Two parts work together: the RR Pocket app on the phone, and the pocket command on your computer.

Requirements

  • A phone running Android 7.0 or later, with RR Pocket from Google Play.
  • A computer running macOS, Linux or Windows, with the Flutter SDK. No Android SDK, no adb.
  • The same Flutter version RR Pocket was built with. Its home screen shows which. A project's compiled code runs only on the engine its SDK was built for.
  • One network for both, where devices can reach each other. Home Wi-Fi works; guest and office networks sometimes keep devices apart.

Install

On the phone, install RR Pocket from Google Play and open it. It shows its address, an 8-character pairing code and the start of its certificate.

On the computer, install the pocket command:

dart pub global activate rr_pocket

If your shell can't find pocket afterwards, add pub's bin folder to your PATH: dart pub global activate prints which folder.

Pair

Pairing gives your computer the phone's address and code, and registers the pocket device with Flutter. You do it once. With RR Pocket open on the phone:

pocket pair

There are three ways to pair. Each is the fallback for the one before.

1. Found on the network

pocket pair looks for the phone on your Wi-Fi for a few seconds, then asks it to pair. The phone asks "Pair with your computer?" and shows the address that asked. Tap Allow. Nothing to type or scan.

2. A QR code

When the network hides the phone, pocket pair shows a QR code instead. Tap Scan QR code in RR Pocket, scan it, and allow the pairing. To go straight to the QR code:

pocket pair --qr

3. Typed

With the address and code RR Pocket shows. This works whenever the computer can reach the phone:

pocket pair 192.168.1.20 H79GN4XS

Check the certificate

When the phone was found or typed, pocket pair prints the start of the phone's certificate, such as 2DC9 1E21. RR Pocket shows the same under its code. If they differ, another device on the network answered first: run pocket forget, then pocket pair --qr. A QR pairing needs no check: the phone proves itself with what it scanned.

Run a project

In your project folder, match its plugin versions to RR Pocket's once, then run:

pocket pin
flutter run -d pocket

Flutter builds your project and sends it to the phone, and your app opens inside RR Pocket. Everything flutter run does works as on any device:

  • r hot reloads, R hot restarts.
  • DevTools, breakpoints and your print output.
  • q quits, and the phone is back on RR Pocket's screen.

Your project needs no android/ folder. The first launch takes a few seconds, longer for a large app; hot reload takes under a second.

Not sure everything is set up? In the project folder:

pocket doctor

It checks the pairing, the phone answering, the Flutter version, the pocket device and the project's plugins, and says what to fix for each.

Commands

CommandWhat it does
pocket pairPair with the phone and add the pocket device to Flutter. Finds the phone on the network, or shows a QR code when it can't.
pocket pair --qrPair by QR code straight away.
pocket pair <address> <code>Pair with the address and code RR Pocket shows.
pocket pinIn a project: pin its Android plugins to RR Pocket's versions in pubspec_overrides.yaml, then run flutter pub get. A breaking change is left out and named.
pocket pin --allPin breaking changes too, once your code is ready for them.
pocket doctorCheck the setup and the project you're in, and say what to fix.
pocket forgetUnpair this computer. The phone keeps its code, so pairing again works.

Flutter calls pocket's other commands itself during flutter run; you don't need them.

Plugins

An app built the usual way carries the Android side of each plugin it uses. Under RR Pocket, your project brings only its Dart code, so RR Pocket carries the Android side of these 29 plugins:

  • camera
  • geolocator
  • flutter_local_notifications
  • local_auth
  • image_picker
  • file_picker
  • url_launcher
  • share_plus
  • shared_preferences
  • path_provider
  • sqflite
  • isar_community
  • flutter_secure_storage
  • video_player
  • just_audio
  • audio_session
  • record
  • webview_flutter
  • permission_handler
  • connectivity_plus
  • device_info_plus
  • package_info_plus
  • battery_plus
  • sensors_plus
  • vibration
  • wakelock_plus
  • in_app_review
  • qr_code_scanner_plus
  • gms_check

The two sides must be the same version, so pocket pin writes RR Pocket's versions into your project's pubspec_overrides.yaml. flutter run stops before sending a project whose versions differ, and names them.

Plain Dart packages, with no Android code, work as they are. A plugin RR Pocket doesn't carry gets a warning: calls to it throw MissingPluginException. Build your app the usual way to try that one.

Lumide

The rr_pocket package is also a plugin for Lumide (0.24.0 or later). Lumide loads it at its next start after dart pub global activate rr_pocket, or install it from Lumide's Plugins pane. Then, from the Command Palette or the status bar:

CommandWhat it does
RR Pocket: Pair with PhoneThe phones found on the network, a QR code to scan, or the address and code typed in.
RR Pocket: Match Plugin Versionspocket pin for the open project.
RR Pocket: Show PhoneThe paired phone, its Flutter version and plugins.
RR Pocket: Check Setuppocket doctor, in the RR Pocket output.
RR Pocket: Forget PhoneUnpair, after asking.

After pairing, pick RR Pocket in the device list and press Run. Lumide and the pocket command share one pairing, so pairing in either is enough.

Troubleshooting

Start with pocket doctor in your project: it names most problems and how to fix them.

pocket pair doesn't find the phone

Some networks block the way devices find each other. pocket pair then shows a QR code: scan it with RR Pocket. If the phone can't reach the computer either, type the address and code: pocket pair <address> <code>. If nothing works, the network keeps devices apart; try another Wi-Fi.

The Flutter version differs

flutter run stops and says which version RR Pocket needs. Run the project with that version, for example with fvm:

fvm use 3.47.7
fvm flutter run -d pocket

Plugin versions differ

Run pocket pin in the project. If it names a breaking change, update your code for that plugin's new version, then run pocket pin --all.

MissingPluginException

Your app calls a plugin RR Pocket doesn't carry. Build your app the usual way to use that one.

The certificate doesn't match

Another device answered when you paired. Unpair and pair by QR code, which can't be answered by anyone else:

pocket forget
pocket pair --qr

The phone's address changed

Phones get a new address on another network, and sometimes on the same one. Run pocket pair again.

"Too many wrong pairing codes"

After 10 wrong codes from one computer, RR Pocket refuses it for 5 minutes. Wait, then pair again with the code the phone shows.

The app stops at start

If your app throws as it starts, RR Pocket shows the error on the phone instead of a frozen screen. Fix it and run again.

You cleared RR Pocket's data

That makes a new pairing code and certificate, so your computer no longer recognizes the phone. Run pocket forget, then pocket pair.

How it works

RR Pocket is an Android app that carries Flutter's debug engine, the one that makes hot reload possible, and the Android side of the plugins above.

  1. flutter run -d pocket builds your project's debug bundle on the computer, as for any device.
  2. The pocket command, which Flutter calls for this device, sends the bundle to RR Pocket over Wi-Fi.
  3. RR Pocket restarts into your app, the same way a hot restart does.
  4. Flutter connects to the app's debugging service through RR Pocket, for hot reload, DevTools and your logs.

Security

RR Pocket runs the code a paired computer sends it, so it guards who can pair:

  • Encrypted. Everything between the computer and the phone goes over TLS. Your computer trusts only the certificate of the phone it paired with.
  • A pairing code on every request. 8 characters, made on the phone. 10 wrong codes lock that computer out for 5 minutes.
  • You allow each pairing on the phone, which shows who asked.
  • Kept private on the computer. The pairing is saved in ~/.config/rr_pocket (%APPDATA%\rr_pocket on Windows), readable only by you.

Pair only computers you trust, on networks you trust. RR Pocket collects nothing; see the privacy policy.
